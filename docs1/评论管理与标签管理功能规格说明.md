# 评论管理与标签管理功能规格说明书

## 1. 功能概述与目标

### 1.1 评论管理功能目标

- 用户可以对社团活动发布评论
- 用户可以回复其他用户的评论（支持评论嵌套，仅支持一级回复）
- 用户可以点赞/取消点赞评论
- 用户可以编辑和删除自己的评论
- 管理员可以管理（查看、删除）所有评论

### 1.2 标签管理功能目标

- 管理员可以对活动标签进行增删改查
- 活动可以关联多个标签（多对多关系）
- 前台用户可以通过标签筛选活动
- 活动详情页展示关联标签

### 1.3 用户场景

#### 评论管理用户场景

1. **学生浏览评论**：学生张三打开某社团活动详情页，可以看到其他同学对该活动发表的评论列表，按时间倒序显示，每条评论包含用户名、内容、发布时间和点赞数。
2. **学生发表评论**：学生张三登录后，在活动详情页底部的评论输入框中输入评论内容（如"这个活动很有趣！"），点击"发布"按钮，评论即刻出现在评论列表中。
3. **学生回复评论**：学生李四看到张三的评论后，点击"回复"按钮，输入回复内容（如"同意，我也想参加！"），提交后回复显示在张三评论的下方。
4. **学生点赞评论**：学生王五觉得张三的评论说得好，点击评论旁的"点赞"图标，点赞数+1；再次点击则取消点赞，点赞数-1。
5. **管理员管理评论**：管理员登录后台，进入评论管理页面，可以查看所有评论列表，对违规评论进行删除操作。

#### 标签管理用户场景

1. **管理员新增标签**：管理员登录后台，进入标签管理页面，点击"新增"按钮，填写标签名称（如"体育"）、类型（如"活动标签"）、排序值，提交后标签创建成功。
2. **管理员编辑标签**：管理员在标签列表中找到需要修改的标签，点击"编辑"按钮，修改标签名称或排序值后保存。
3. **管理员删除标签**：管理员选择一个或多个不再使用的标签，点击"删除"按钮，确认后标签被删除，同时自动解除与活动的关联关系。
4. **用户通过标签筛选活动**：学生在前台活动列表页看到标签筛选栏，点击"体育"标签后，列表仅显示关联了"体育"标签的活动。
5. **活动详情页展示标签**：学生在活动详情页可以看到该活动关联的所有标签（如"体育"、"户外"），以标签徽章形式展示在标题下方。

## 2. 数据库设计

### 2.1 现有表结构

#### discuss 评论表

| 字段名 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| id | BIGINT | AUTO_INCREMENT | 主键ID |
| content | VARCHAR(500) | - | 评论内容 |
| user_id | BIGINT | - | 评论用户ID |
| user_name | VARCHAR(200) | - | 评论用户名称 |
| object_type | VARCHAR(50) | - | 被评论对象类型（如"shetuanhuodong"表示社团活动） |
| object_id | BIGINT | - | 被评论对象ID |
| parent_id | BIGINT | 0 | 父评论ID（用于回复功能，0表示顶级评论） |
| like_count | INT | 0 | 点赞数 |
| status | VARCHAR(20) | '正常' | 状态（正常/已删除/已屏蔽） |
| create_time | DATETIME | CURRENT_TIMESTAMP | 创建时间 |

#### tag 标签表

| 字段名 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| id | BIGINT | AUTO_INCREMENT | 主键ID |
| name | VARCHAR(100) | - | 标签名称 |
| type | VARCHAR(50) | - | 标签类型（活动标签、社团标签等） |
| sort | INT | 0 | 排序值（越小越靠前） |
| status | VARCHAR(20) | '正常' | 状态（正常/禁用） |
| create_time | DATETIME | CURRENT_TIMESTAMP | 创建时间 |

### 2.2 新增表结构

#### activity_tag 活动标签关联表

| 字段名 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| id | BIGINT | AUTO_INCREMENT | 主键 |
| activity_id | BIGINT | - | 活动ID（关联shetuanhuodong.id） |
| tag_id | BIGINT | - | 标签ID（关联tag.id） |
| create_time | DATETIME | CURRENT_TIMESTAMP | 创建时间 |

### 2.3 SQL语句

```sql
-- 创建活动标签关联表
CREATE TABLE `activity_tag` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键',
  `activity_id` BIGINT NOT NULL COMMENT '活动ID（关联shetuanhuodong.id）',
  `tag_id` BIGINT NOT NULL COMMENT '标签ID（关联tag.id）',
  `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_activity_tag` (`activity_id`, `tag_id`),
  KEY `idx_activity_id` (`activity_id`),
  KEY `idx_tag_id` (`tag_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='活动标签关联表';

-- 如果discuss表尚未创建，以下为建表SQL
CREATE TABLE IF NOT EXISTS `discuss` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `content` VARCHAR(500) NOT NULL COMMENT '评论内容',
  `user_id` BIGINT NOT NULL COMMENT '评论用户ID',
  `user_name` VARCHAR(200) DEFAULT NULL COMMENT '评论用户名称',
  `object_type` VARCHAR(50) NOT NULL COMMENT '被评论对象类型',
  `object_id` BIGINT NOT NULL COMMENT '被评论对象ID',
  `parent_id` BIGINT DEFAULT 0 COMMENT '父评论ID（0表示顶级评论）',
  `like_count` INT DEFAULT 0 COMMENT '点赞数',
  `status` VARCHAR(20) DEFAULT '正常' COMMENT '状态',
  `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  PRIMARY KEY (`id`),
  KEY `idx_object` (`object_type`, `object_id`),
  KEY `idx_parent_id` (`parent_id`),
  KEY `idx_user_id` (`user_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='评论表';

-- 如果tag表尚未创建，以下为建表SQL
CREATE TABLE IF NOT EXISTS `tag` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `name` VARCHAR(100) NOT NULL COMMENT '标签名称',
  `type` VARCHAR(50) NOT NULL COMMENT '标签类型',
  `sort` INT DEFAULT 0 COMMENT '排序值',
  `status` VARCHAR(20) DEFAULT '正常' COMMENT '状态',
  `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_name_type` (`name`, `type`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='标签表';
```

## 3. API接口规格

### 3.1 评论管理API

#### 3.1.1 POST /discuss/save — 发布评论

- **接口地址**: `POST /discuss/save`
- **认证要求**: 需要登录（通过Session获取userId）
- **请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| content | String | 是 | 评论内容（1-500字符） |
| objectType | String | 是 | 被评论对象类型，固定值为 `"shetuanhuodong"` |
| objectId | Long | 是 | 被评论对象ID（活动ID） |
| userName | String | 否 | 评论用户名称 |
| parentId | Long | 否 | 父评论ID，不传或传0表示顶级评论 |

- **请求示例**:
```json
{
  "content": "这个活动太棒了，强烈推荐！",
  "objectType": "shetuanhuodong",
  "objectId": 1650000000001,
  "userName": "张三",
  "parentId": 0
}
```

- **成功响应**:
```json
{
  "code": 0,
  "msg": "success"
}
```

- **失败响应**:
```json
{
  "code": 500,
  "msg": "请先登录"
}
```

- **业务逻辑说明**:
  - 从Session中获取当前登录用户的 `userId`，若未登录则返回错误
  - 自动设置 `userId` 为当前用户ID
  - 自动设置 `createTime` 为当前时间
  - 自动设置 `likeCount` 为0
  - 自动设置 `status` 为"正常"
  - 调用 `discussService.insert()` 保存评论

## 5. 业务规则与校验

### 5.1 评论业务规则

1. **评论内容长度限制**: 评论内容长度在1-500字符之间，不能为空且不能超过500字符。前端和后端均需校验。
2. **回复嵌套深度**: 仅支持一级回复，即 `parentId` 只能引用顶级评论（`parentId = 0` 的评论）的ID。不允许回复的回复（即不允许 `parentId` 指向另一条已有 `parentId` 的评论）。
3. **点赞限制**: 每个用户对每条评论只能点赞一次。可通过 `storeup` 表记录点赞行为：`tablename = "discuss"`，`refid = 评论ID`，`userid = 用户ID`。点赞前检查是否已存在记录，存在则不允许重复点赞。
4. **编辑/删除权限**:
   - 普通用户仅能编辑和删除自己发布的评论
   - 管理员可删除任何评论（管理后台操作）
   - 删除顶级评论时，建议同时删除其所有回复
5. **评论状态管理**:
   - `正常`：默认状态，正常展示
   - `已屏蔽`：管理员屏蔽后，前台不展示，后台可见
   - `已删除`：逻辑删除或物理删除

### 5.2 标签业务规则

1. **标签名称唯一性**: 同一类型（`type`）下标签名称（`name`）必须唯一。新增和修改时需校验。
2. **标签排序规则**: 按 `sort` 字段正序排列（值越小越靠前），`sort` 值相同时按 `create_time` 正序排列。
3. **标签状态切换**:
   - `正常`：标签可正常使用，前台可见，可关联活动
   - `禁用`：标签不可使用，前台不展示，但不影响已有关联关系
4. **删除标签联动**: 删除标签时，必须同步删除 `activity_tag` 关联表中该标签的所有关联记录，防止产生脏数据。
5. **活动绑定标签数量**: 建议每个活动最多关联10个标签。

| POST /discuss/unlike/{id} | 是 | 已登录用户 | 需校验是否已点赞 |
| GET /discuss/page | 是 | 管理员 | 后台管理页面专用 |

### 6.2 数据校验

1. **输入验证规则**:
   - 评论内容：非空，长度1-500字符，去除首尾空格
   - 标签名称：非空，长度1-100字符，去除首尾空格
   - 标签类型：非空，限定可选值（活动标签/社团标签）
   - ID参数：必须为正整数
   - 数组参数（如ids）：非空，元素必须为正整数

2. **XSS防护**:
   - 评论内容入库前进行HTML转义处理（转义 `<`、`>`、`&`、`"`、`'` 等特殊字符）
   - 前端展示时使用文本模式渲染（`v-text` 或 `textContent`），避免使用 `v-html` 或 `innerHTML`
   - 标签名称同样需要XSS过滤

3. **防重复提交**:
   - 前端发布评论按钮在请求期间禁用（loading状态）
   - 后端可通过短时间内相同用户、相同内容、相同对象的评论去重
   - 点赞操作通过 `storeup` 表的唯一性约束防止重复

## 附录：技术栈参考

| 技术 | 说明 |
|------|------|
| Spring Boot | 后端框架 |
| MyBatis-Plus | ORM框架，使用 `EntityWrapper` 构建查询条件 |
| Vue.js + Element UI | 管理后台前端框架 |
| 原生HTML/CSS/JS | 前台用户界面 |
| `R` 工具类 | 统一响应格式，`R.ok()` 返回 `code:0`，`R.error()` 返回 `code:500` |
| `PageUtils` | 分页工具类，封装分页结果 |
| `Query` | 查询工具类，封装分页参数 |
| `MPUtil` | MyBatis-Plus辅助工具类，提供 `likeOrEq`、`sort`、`between` 等方法 |
| `@IgnoreAuth` | 自定义注解，标记不需要登录认证的接口 |
| `storeup` 表 | 收藏/点赞通用表，通过 `tablename` 区分业务类型 |
